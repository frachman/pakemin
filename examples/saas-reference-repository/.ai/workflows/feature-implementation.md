# Feature Implementation Workflow

## Purpose

Use this workflow when adding or changing product behavior.

## Steps

1. Read relevant context and rules.
2. Identify affected tenants, permissions, and data flows.
3. Make the smallest coherent change.
4. Add or update focused tests.
5. Update memory, context, or ADRs if the change creates durable knowledge.
6. Report assumptions, validation, and follow-up work.
